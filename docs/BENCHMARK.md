# Нагрузочные измерения

Актуальное сопоставление Qwen2.5-1.5B и Qwen3-4B на одинаковых лимитах: [COMPARISON.md](COMPARISON.md). Ниже сохранены методика и результаты первоначального прогона Qwen2.5.

## Методика

Бенчмарк отправляет потоковые HTTP-запросы к уже запущенному серверу. Проверяется завершение SSE потока и наличие статистики токенов. При `--ignore-eos` каждый успешный ответ должен содержать ровно заданное число выходных токенов.

Первоначальный прогон: 50 запросов на случай, параллельность 1, 2 и 4, короткий и длинный вход, 128 выходных токенов, три прогревочных запроса на случай. Всего 300 измеряемых и 18 прогревочных запросов. Перед общим текстом ставится уникальный идентификатор, чтобы повторение одного префикса не создавало искусственный выигрыш от кэша.

Нагрузка замкнутая: одновременно выполняется не более заданного числа запросов. Задержка отсчитывается от фактического HTTP-запроса, без ожидания очереди клиентского executor. Готовый отчёт хранит каждый результат и ошибки без текстов запросов и ответов.

| Метрика | Определение |
| --- | --- |
| TTFT | Время от начала HTTP-запроса до первого непустого фрагмента ответа |
| Latency | Время от начала запроса до SSE `[DONE]` |
| TPOT | `(latency - TTFT) / (output_tokens - 1)`, включая завершение потока |
| Output tokens/s | Сумма выходных токенов / длительность измеряемого случая |
| Requests/s | Успешные запросы / длительность случая |
| p95 | Метод ближайшего ранга |
| GPU memory | Показания `nvidia-smi` для всей видеокарты, включая Windows и другие процессы |

Телеметрия GPU снимается примерно раз в секунду и включает прогрев. Пиковое значение может пропустить короткий всплеск между отсчётами. Показания памяти всей карты нельзя считать объёмом одних весов модели.

## Воспроизведение первоначального прогона

```powershell
python scripts/check_gpu.py
python scripts/benchmark.py --requests 50 --concurrency-levels 1 2 4 --max-tokens 128 --warmup-requests 3 --ignore-eos --gpu-metrics
```

Настройки сервера находятся в `config/inference.json`; параметры окружения записывает `check_gpu.py`. Измерения имеют смысл сравнивать при одинаковых весах, точности, длинах входа и выхода и сопоставимых условиях питания и температуры ноутбука.

## Первоначальные результаты Qwen2.5

Дата локального прогона: 15 ноября 2026, Москва. Windows / WSL 2, Docker Compose, Qwen2.5-1.5B-Instruct BF16, RTX 5070 Ti Laptop 12 ГБ. Лимиты контейнера: 6 CPU и 12 ГиБ RAM. Вход содержит 81 токен в коротком случае и 916 токенов в длинном, включая шаблон чата и идентификаторы.

Все 300 запросов завершились без ошибок и вернули по 128 выходных токенов. Параллельность обозначена `C`.

| Вход | C | TTFT p50 / p95, мс | Latency p50 / p95, с | TPOT p50, мс | Токенов/с | GPU пик, МиБ |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Короткий | 1 | 27.9 / 45.8 | 1.144 / 2.016 | 8.73 | 103.58 | 9486 |
| Длинный | 1 | 79.6 / 92.2 | 1.204 / 1.265 | 8.85 | 105.39 | 9491 |
| Короткий | 2 | 32.0 / 53.0 | 1.159 / 1.241 | 8.86 | 214.65 | 9492 |
| Длинный | 2 | 121.1 / 148.6 | 1.268 / 3.174 | 9.15 | 175.41 | 9488 |
| Короткий | 4 | 38.7 / 52.1 | 1.157 / 1.230 | 8.76 | 431.85 | 9485 |
| Длинный | 4 | 191.4 / 2256.0 | 1.409 / 3.363 | 9.57 | 316.75 | 9485 |

При четырёх параллельных коротких запросах получено 431.85 выходного токена/с, при длинных 316.75. Медианная задержка короткого запроса осталась около 1.16 с, а длинного выросла до 1.41 с. При длинном входе и C=4 время до первого токена имеет заметный хвост: p95 составляет 2.26 с. Для сценария со строгой задержкой это повод проверять меньшую параллельность, несмотря на выигрыш общей пропускной способности.

Это один прогон на ноутбуке с Windows. Телеметрия и индивидуальные измерения сохранены без удаления выбросов. Причина отдельных длинных задержек этим экспериментом не установлена.

## Выбор настроек

Для большого числа коротких запросов увеличение параллельности позволяет объединять вычисления, но повышает ожидание первого токена. Для длинного контекста существеннее стоимость обработки входа и объём KV-кэша; лимиты `max_num_seqs`, `max_model_len` и `max_num_batched_tokens` стоит подбирать по задержке и доступной памяти.

Этот прогон характеризует одну видеокарту и одну модель. Он не устанавливает универсальный максимум и не измеряет качество ответов. Сравнение с CPU требует отдельного прогона той же модели с теми же параметрами.
